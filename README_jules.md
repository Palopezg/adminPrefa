# adminPrefa - Project Overview (README_jules.md)

`adminPrefa` is an administration panel designed for managing preferences and configurations related to telecommunication/media services, decoder devices (like set-top boxes), and their specific characteristics. It allows users to define and manage service types, decoder models, features, and various operational parameters.

This application was generated using [JHipster](https://www.jhipster.tech/) version 6.8.0.
*   **Backend:** Spring Boot
*   **Frontend:** React
*   **Database:** H2 in-memory for development (default), with Oracle being a likely production target (configurable in Spring profiles).

This document provides a detailed overview of the project, including its data model, API structure, setup instructions, and development workflow.

## Data Model

The application manages several key entities:

### 1. `ServiceType`
*   **Purpose:** Defines the types of services that can be configured or offered (e.g., broadband internet, IPTV, VoIP).
*   **Key Fields:**
    *   `serviceId` (String): A unique identifier for the service type.
    *   `descripcion` (String): A textual description of the service type.
*   **Source File:** `.jhipster/ServiceType.json`

### 2. `TipoDeco`
*   **Purpose:** Represents the different types or models of decoder devices (e.g., set-top boxes for television services).
*   **Key Fields:**
    *   `tipoDeco` (String): The specific model or type name of the decoder. (Required)
    *   `tecnologia` (Enum: `FTTH`, `HFC`, `COBRE`): The underlying technology the decoder uses. (Required)
    *   `multicast` (String): Indicates multicast capability or configuration. (Required)
*   **Source File:** `.jhipster/TipoDeco.json`

### 3. `Characteristic`
*   **Purpose:** Describes specific features, attributes, or capabilities that can be associated with a service.
*   **Key Fields:**
    *   `characteristicId` (String): A unique identifier for the characteristic. (Required)
    *   `descripcion` (String): A textual description of the characteristic.
*   **Relationships:**
    *   Many-to-one with `ServiceType`: A service type can have multiple characteristics, but a characteristic is typically associated with one service type (based on `otherEntityField: "descripcion"` in the JHipster JSON, this might imply the `ServiceType`'s description is used for display in relation to a characteristic).
*   **Source File:** `.jhipster/Characteristic.json`

### 4. `Parametros`
*   **Purpose:** A general-purpose entity for storing key-value configuration parameters that might be used across the application.
*   **Key Fields:**
    *   `parametro` (String): The name of the parameter (the key). (Required)
    *   `valor` (String): The value associated with the parameter. (Required)
*   **Source File:** `.jhipster/Parametros.json`

These entities form the core of the `adminPrefa` system, allowing for detailed configuration and management of services and equipment.

## Setup and Development Workflow

This section describes how to set up, run, test, and build the `adminPrefa` application.

### Prerequisites
Before you begin, ensure you have the following installed:
*   **Java Development Kit (JDK):** Version 1.8 (as specified in `pom.xml`).
*   **Node.js:** Version 12.16.1 or compatible (as specified in `pom.xml`). You can use [nvm](https://github.com/nvm-sh/nvm) to manage Node versions.
*   **npm:** Version 6.14.2 or compatible (usually comes with Node.js).
*   **Maven:** Version 3.3.9 or higher (as specified in `pom.xml`).
*   **(Optional) Docker:** For running databases or other services in containers.

### Backend Development (Spring Boot)

The backend is a Spring Boot application managed with Maven.

*   **Running the backend (development mode):**
    Open a terminal in the project root and run:
    ```bash
    ./mvnw
    ```
    This will start the Spring Boot application. By default, it's usually accessible at `http://localhost:8080`.
    The backend will connect to the database configured in `src/main/resources/config/application-dev.yml` (typically an H2 in-memory database for development).

*   **Running backend tests:**
    ```bash
    ./mvnw verify
    ```
    This command runs all backend unit and integration tests.

### Frontend Development (React)

The frontend is a React application managed with npm.

*   **Installing frontend dependencies:**
    Navigate to the project root in a terminal and run:
    ```bash
    npm install
    ```
    This command should be run once initially and whenever dependencies in `package.json` change.

*   **Running the frontend (development mode with hot reload):**
    In a separate terminal (while the backend is running), execute:
    ```bash
    npm start
    ```
    This starts the Webpack development server, typically on `http://localhost:9060`. It will automatically proxy API requests (e.g., to `/api`) to the backend server running on port 8080. The browser will auto-refresh when frontend files change.

*   **Running frontend tests:**
    ```bash
    npm test
    ```
    This runs Jest unit tests located in `src/test/javascript/spec/`.

### Building for Production

To build the application for a production environment:

1.  **Package the application (Jar):**
    ```bash
    ./mvnw -Pprod clean verify
    ```
    This command cleans the project, builds the frontend (optimized for production), runs all tests, and packages the application as an executable JAR file in the `target/` directory.

2.  **Run the production build:**
    ```bash
    java -jar target/*.jar
    ```
    (Replace `*.jar` with the actual JAR file name). The application will start using production settings, typically from `src/main/resources/config/application-prod.yml`.

### Database Configuration
*   **Development:** Uses the H2 in-memory database by default (see `src/main/resources/config/application-dev.yml`).
*   **Production:** You'll need to configure a persistent database (e.g., PostgreSQL, MySQL, Oracle) in `src/main/resources/config/application-prod.yml`. The original `README.md` mentions Oracle, and `ojdbc8` is a dependency in `pom.xml`, suggesting Oracle is a likely production target.
